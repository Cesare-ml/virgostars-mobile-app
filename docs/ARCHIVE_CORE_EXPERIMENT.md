# Android encrypted chart archive

Status: **experimental, implemented on Android**; not a released or independently audited security product. iOS, accounts, profile isolation, synchronization, archive export and recovery are not implemented.

The new-chart form always saves inputs (name, UTC instant, time zone, coordinates and optional place name) before calculation. If saving fails, calculation does not proceed. The record is kept even when calculation fails, and retrying the same failed calculation updates that record. The user can search saved names and places, update an opened record after confirmation, open or delete it with confirmation, and create a separate election chart at the navigated time. Comparison controls are temporarily hidden. Opening recalculates the chart, so compatible locally installed ephemeris data are required. A bounded, validated list/save/delete IPC contract is the only archive interface; it accepts no filesystem paths or legacy migration operation.

## Storage and key lifecycle

The desktop-derived core serializes an in-memory SQLite database, seals it using XChaCha20-Poly1305 with a fresh nonce on each write and atomically replaces the previous encrypted container. SQLite temporary storage is in memory. It limits the number of charts and the container size. A random 256-bit data key is wrapped using AES-GCM by an Android Keystore key, and only the wrapped key and encrypted container are stored under the app's `getNoBackupFilesDir()`. The wrapping key does not leave Keystore; the data key is temporarily unwrapped in native process memory, not sent to the WebView. This is one device-local archive for the app installation, not a per-account vault. See [Android Keystore](https://developer.android.com/privacy-and-security/keystore) and [Android backup behavior](https://developer.android.com/identity/data/autobackup).

Uninstall, data clearing, or loss/invalidation of the key makes the archive unrecoverable. The no-backup directory is excluded from Android automatic backup and device transfer; there is no recovery or export mechanism. A missing or invalid key locks the archive rather than replacing it or falling back to plaintext. Inherited desktop plaintext migration/removal code is disabled on mobile. Normal OS/app update preservation, hardware-backed security, power-loss behavior and Android vendor differences need physical-device testing; no guarantee is made for compromised devices.

## Verification and remaining work

The core is adapted from desktop commit `023d76d` (CPAL-1.0). Host Rust tests cover round trips, ciphertext, tampering, missing/wrong keys, failed writes and rejection of legacy migration in mobile mode; synthetic TypeScript tests check the IPC validation. On an Android x86_64 emulator, a debug build saved a fictional chart using the real platform Keystore, reopened it after an emulator restart and app update, updated it without duplication and deleted it after confirmation. Removing the wrapped-key file produced a locked state without changing the encrypted container; restoring it recovered access. The test container contained neither the fictional name nor an SQLite plaintext header. This does not establish physical-device, backup/restore, interrupted-write, actual Keystore invalidation, performance or security-audit coverage. Run `cargo test --offline --manifest-path src-tauri/Cargo.toml --features archive-experimental --lib` and `npm run check` for local regression coverage.
