# Desktop Lab 0.0.1 parity checkpoint

Target: VirgoStars Desktop Lab 0.0.1, built from desktop commit `023d76d`. This is an implementation target, not a claim that the mobile app has reached parity. The desktop release is experimental and its 1900–2033 range and DE441 data are not automatically available on mobile.

For the current first implementation the user has deferred solar/lunar returns, direct chart touch/highlighting and PNG export. They remain documented below as broader parity information, not current priorities. The first Android release is intended to retain current features and add sign-in, account chart synchronization and dodecatemoria, followed by interface refinement and release validation.

Both apps are offline prototypes; neither a login nor server synchronization is implied by the parity target. Display settings are stored locally without chart data. The aspect settings and desktop-style pairing policy derive from VirgoStars Desktop commit `023d76d` (CPAL-1.0); shared geometry is supplied by `astrological-functions`. Phi contacts can differ from drawn lines across 0° Aries, as documented in desktop `docs/ASPECTS_AND_ORBS.md`. Validate provider/data licences, shared contracts, DST behavior, accessible touch interaction, device memory and WebGL recovery before distribution. See the historical [Android emulator checkpoint](ANDROID_PARITY_SMOKE_2026-11-17.md).

The experimental trend adapter checks the pinned VirgoStars provider, matching chart/UTC/angles, and JPL, small-body or core-model lunar-point longitude/rate before evaluating; derived lunar antipodes must match the source longitude and rate. Axes are fixed in natal charts; transit natal points are fixed. It intentionally omits unsupported/missing rates and all synastry trends. Kernel identity, exact rate uncertainty and independent numerical accuracy are not established; A/S is labelled experimental, not scientific certification. The module is accessed from the existing private sibling checkout and is not yet an exported stable package API.

On 2026-11-18 an Android 36.1 x86_64 emulator debug build used real local DE441 data and fictional charts to exercise saving before calculation, sky navigation, confirmed update, election-chart creation, archive search, selecting a startup chart and, after a process restart, reopening it with current transits and choosing a second saved chart for comparison. The app now stores the startup mode and optional chart UUID in an app-private no-backup file: WebView local storage did not persist reliably across forced stops in this emulator. Test records and the test startup preference were removed. Synthetic Chromium coverage separately tested saving when calculation fails, idempotent retry, held stepping, month adjustment and cancellation of a delayed startup. These checks do not establish physical-device behavior, power-loss durability, complete accessibility or numerical correctness.

On 2026-11-17 a local Android 36.1 x86_64 emulator debug build loaded the expanded catalog, found Landriano with a country-qualified query, and calculated a fictional J2000 chart using a temporary external DE441 file. The aspects panel contained 20 rows and 14 experimental A/S marks; a second fictional chart produced marked transits and no synastry marks. WebView events drove the test, and an emulator screenshot was visually inspected. A subsequent change added modeled lunar-point and antipode marks and stricter source checks; these were covered by synthetic tests, not that emulator run. This does not establish scientific correctness, a full line-by-line comparison with the renderer, physical-device behavior or low-memory performance. The temporary DE441 file and debugging connection were removed after the check.
