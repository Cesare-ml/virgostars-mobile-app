# Solar and lunar returns — isolated transport contract

Status: **Locally tested, isolated prototype**. The TypeScript contract and synthetic tests derive from VirgoStars Desktop `023d76d` (CPAL-1.0); the mobile application does not import the contract, register `find_returns`, or offer a return-search UI. No return computation has been enabled.

The proposed request contains exactly a Sun/Moon identifier, a finite target longitude in `[0, 360)` degrees and a Gregorian UTC year from 1600 through 2400. The adapter snapshots data properties before calling an injected transport and forwards no chart names, birth dates, coordinates or paths. Exceptions and malformed native responses become generic failure states. Success requires a bounded, strictly chronological list with matching canonical UTC millisecond timestamps and Julian days, both within the requested `[1 January, 1 January next year)` UTC interval. Returned objects are detached and frozen. These checks protect the adapter boundary; they do not establish that a result is astronomically correct or that the search is complete.

The desktop search rounds event times to milliseconds. An event within half a millisecond of the end of the requested year can round into the next year: this contract rejects such an ambiguous boundary result instead of silently displaying it as belonging to the requested year. A shared solver and its eventual mobile bridge must explicitly resolve the half-open-year and rounding policy before integration. The adapter also rejects repeated timestamps at millisecond precision and more than two solar or sixteen lunar events; those are defensive protocol bounds, not completeness guarantees.

`node --experimental-strip-types --test tests/return-search-contract.test.mjs` checks synthetic transport results and failures. It does not run a native search, prove physical accuracy, test a device, or validate performance. The current chart provider and the prospective return provider also need explicit matching source, frame, time scale and correction metadata. The chart form and session/navigation paths now preserve local seconds and milliseconds in synthetic browser and timezone tests, but the future return-chart action must still pass the exact returned UTC instant and be tested end to end; no return action exists yet. UI lifecycle, stale-request cancellation, relocation, error handling and provider provenance need their own tests before activation.

The mobile project assigns astrology calculations to the shared engines. The desktop-local numerical solver is therefore not copied into this app. A shared, bounded solver with documented motion/coverage assumptions, independent numerical validation, and an appropriate provider integration is still required. The optional Swiss provider remains local-use only and disabled by default; no distribution rights or DE441 parity follow from these tests.
