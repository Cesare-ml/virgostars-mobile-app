# Historical GeoNames experiment — superseded

This document records a previous experiment. GeoNames is no longer used or shipped by the app; the current Android implementation uses the desktop catalog described in [DESKTOP_CITIES.md](DESKTOP_CITIES.md). The statements below describe historical builds only.

The local search uses a modified extract of [GeoNames cities1000](https://download.geonames.org/export/dump/), licensed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Attribution appears next to the search in the app. The source is the gazetteer, not the separate postal-code dataset. Source snapshot downloaded 2026-11-17; archive SHA-256 `3ecb9ec088363cf88153f4459d32a2843497dcf386af60585f98817650c1df65`; generated JSON SHA-256 `76913c55e5ae89e187d8258de09b77424142b5e146ef47e676f2332497e031f6`.

The derivative contains 172,021 entries, filters out rows without an IANA time zone, keeps only selected fields and up to 150 alternative names of at most 50 characters, and orders entries by population. Region is the GeoNames admin1 code, not a translated region name. Country names are displayed using the device's localized Unicode data with the ISO code alongside. Search accepts a place alone, `place, country` (ISO code or Italian/English country name), or `place, region code, country`. Exact names and aliases rank before prefix matches, then substring matches; within each category the catalog's population order is preserved. Search is entirely local; no birth data or search query is sent to a service. `cities1000` does not include all settlements and does not reproduce the desktop's private city database; it is not an authority on historical time zones or political boundaries. Coordinates and IANA time zone remain editable.

For reproducibility, obtain the exact archive with the hash above and run `python scripts/build-geonames-1000.py input.zip output.json`. The script refuses a different source hash and refuses to overwrite an existing file. The previous 70,042-entry cities5000 snapshot is retained in the source tree but excluded from the app build. The upstream data changes over time, so updating requires a new source hash, review and attribution update. The approximately 30.7 MB JSON is loaded and searched in an app-owned Web Worker on first search; only bounded matching records return to the interface. The worker is terminated after 60 seconds with no pending search and is recreated on demand, allowing its catalog memory to be released. If workers are unavailable or fail, the original local main-thread search remains available. The worker reduces main-thread blocking but does not reduce peak catalog memory; physical-device and low-memory performance still require verification.
## Local emulator verification — 2026-11-16

On the dedicated Android 36.1 x86_64 emulator, with Wi-Fi and mobile data disabled, searching `Roma` selected GeoNames Rome (IT), filled `41.89193`, `12.51133` and `Europe/Rome`, and calculated the fictional 2000-01-01 12:00 civil input as 11:00 UTC. The Swiss/Moshier result and synthetic chart wheel appeared. This verifies one offline end-to-end case, not full catalog accuracy or a physical device.

On 2026-11-17, a separate Android 36.1 x86_64 emulator debug run loaded the 172,021-entry catalog and selected Landriano via a country-qualified query; a fictional DE441 chart was then calculated. This run used the WebView debug interface and did not establish physical-device or low-memory performance.

On 2026-11-18, an Android 36.1 x86_64 emulator debug build received three actual worker responses for `Roma, IT`, `San Pietro`, and `Landriano, IT`, with no observed worker errors; the exact-match ordering put San Pietro a Maida before longer prefix matches. A Chromium synthetic test also exercised latest-query handling and the no-worker fallback. The emulator test used WebView debugging and did not measure physical-device memory or responsiveness under load.
